# 配置文件格式 v2

在工作台顶部打开「导入 / 导出」。文件均为 UTF-8 JSON，文件格式版本与插件版本独立。

- **导出当前配置**：随机指令页在原模式导出当前组，剧情增强模式导出两层所用组；技能页导出当前聊天正在编辑的技能表，包含尚未「保存到组」的修改。可改导出名称，不改原组名称，也不更新组库。
- **选择配置组导出**：勾选一组、多组或全选；导出组库保存版本，不包含当前聊天尚未保存到组的技能修改。
- **导入**：选择文件，检查类型、名称、数量和重名后的名称，再点击「导入为新组」。不会覆盖配置、切换当前组、载入技能表或清除待检定记录。
- **下载示例模板**：下载[可直接导入的混合示例](../templates/config-example.json)，也可按下表手写或生成模板。

## 文件与字段

顶层 `format` 固定为 `"auto-random-input"`，新导出使用 `formatVersion: 2`，同时读取旧 `formatVersion: 1`。`randomGroups`、`skillGroups` 是数组，可以只提供其中一种，但合计至少一个组。技能表使用技能加值配置，不提供旧版成功阈值转换。

随机指令组：

| 字段 | 内容 |
| --- | --- |
| `name` | 非空组名 |
| `rules` | 至少一套骰子指令；旧模式按此顺序发送，剧情增强模式统一调度 |
| `rules[].name` | 非空指令名称 |
| `rules[].diceSides` | 整数 1～10、20 或 100 |
| `rules[].enabled` | 布尔值，省略为 `true` |
| `rules[].commands` | 最多20条字符串，按位置对应1～20点；可省略或少填，末尾补空。空白占骰面，不会自动移除 |
| `rules[].ranges` | d100 范围表，可省略为空数组；每行有字符串 `range`、`command` |
| `rules[].commandMetadata` | 与普通骰子20个字符串槽位对应的元数据数组，可省略 |
| `rules[].ranges[].metadata` | 对应d100范围行的同等元数据，可省略 |

范围可写 `"1-20"` 或 `"50"`，包含首尾，允许空档及空白命令。当前骰型为 d100 时，范围须在1～100内且不重叠。其他骰型的范围草稿原样保留。导出始终保留全部20个命令槽位及范围表，切换骰型后的隐藏内容也在文件里。

元数据字段：

| 字段 | 内容 |
| --- | --- |
| `effect` | `event`（实质变化）或 `detail`（氛围细节），默认 `event` |
| `topic` | `daily`、`relationship`、`clue`、`opportunity`、`obstacle`、`conflict`、`callback`、`atmosphere`、`general`，默认 `general` |
| `conditions` | AND 条件数组，默认 `[]` |
| `persistent` | 用户显式设为常驻要求，仅d1允许，默认不启用 |
| `needsBinding` | 剧情线专属条目跨聊天分享后的待绑定标记；为true时不会触发 |

条件采用白名单对象：`type: "stat"` 配 `path`、`op`、`value`；`path` 为 `stat_data.` 开头的精确路径，操作为 `eq/ne/gt/gte/lt/lte/contains`。`type: "label"` 配场景标签 `value`。`type: "thread"` 配剧情线身份和状态，但本地身份不随分享携带，导入后需要重新绑定。类型不符、缺失变量和未绑定条件均不成立，不执行表达式或脚本。

v1文件或缺少元数据的旧条目默认「实质变化／未分类／无条件／非常驻」。旧模式行为保持原样；切换到剧情增强模式后才参加预算和条件调度。剧情线专属指令分享后保留待绑定要求，不能通过删除本地身份变成无条件触发。

技能配置组：

| 字段 | 内容 |
| --- | --- |
| `name` | 非空组名 |
| `diceSides` | 数字 10、20 或 100 |
| `mode` | `"challenge"` 或 `"every"`，省略为 `"challenge"` |
| `maxChecks` | 数字1、2或3，省略为1 |
| `pointLimitMode` | `"auto"` 或 `"custom"`，省略为 `"auto"` |
| `pointLimit` | 自定义预算必填，为非负整数；自动预算按技能数量和骰型重新计算 |
| `skills` | 至少一项技能，保留原顺序 |
| `skills[].name` | 非空技能名，去除首尾空格后不能重复 |
| `skills[].modifier` | 整数加值，必填；正数写 `4`，不要写 `+4` 或字符串 `"4"` |

加值上下限沿用当前规则：d10 为 −2～+10，d20 为 −4～+20，d100 为 −20～+100。净和不能超过总预算。自动预算每项分别为2、3、15点。

## 分享与校验

内部 ID 在导入时重新生成，同类组库重名自动加空格和序号；一个文件内的重复组名同样处理。文件不携带全局开关、界面主题、聊天绑定、聊天记录、剧情事实、偏好反馈、待检定事件、历史骰点或迁移快照。条目的剧情主题分类属于可分享配置。只读取上述配置字段，不执行文件中的内容。

非法格式版本、字段类型、当前骰型的范围错误或技能错误会阻止本次导入／导出，并显示具体组名和位置。整个文件校验通过后才加入配置库，不会部分导入。没有打开聊天时仍可导入或导出组库，但不能导出当前技能表。

常见流程：在界面配置 → 导出当前配置 → 分享 `.json` → 对方选择文件 → 预览 → 导入为新组 → 自行切换或载入。
