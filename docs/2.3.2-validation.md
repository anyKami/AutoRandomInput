# 2.3.2 重新生成后的 HTML 渲染验证

2026-11-10：本地聊天的用户消息包含数据库召回包装和 HTML 面板美化正则。首次发送时，酒馆正常发出用户消息渲染事件；插件在重新生成时直接调用 `updateMessageBlock`，没有发出更新事件，导致酒馆助手没有重新渲染 HTML 代码块。

另一个问题是，角色卡正则改写了检定提示里的 XML 示例，原注入片段因此无法完全匹配。恢复时又追加了一份检定提示。

修复范围：

- 已渲染的消息更新后，发出 `MESSAGE_UPDATED`；新消息仍由酒馆按原流程通知，未渲染的历史消息不访问 DOM。
- 消息里已包含该批次请求 ID 时沿用已有说明，不因包装或局部改写再次追加。此判断仅用于去重，不限制检定执行。
- 内置提示用标签名称说明 XML 结构，避免示例被角色卡变量正则当成实际更新块处理。

验证：`npm test` 共 100 项通过。回归覆盖重新生成时先刷新 DOM 再通知渲染、连续重试不重复刷新、召回内的改写提示不重复追加，以及历史清理通知。

对本地最新用户消息进行内存副本回放：重发没有追加第二份说明，已有骰点未变化；新提示通过变量更新正则后保持完整。

未修改角色卡、用户正则配置或真实聊天记录，没有触发模型生成。
