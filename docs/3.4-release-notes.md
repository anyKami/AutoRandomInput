# 随机指令工作台 3.4.0：自动生成追加模式

## 新增

在 **设置 → 自动生成随机指令** 中新增「**在现有指令后追加（不新建配置组）**」复选框，默认关闭，按聊天保存。

- 未勾选：保持原有逻辑。一个聊天复用一个自动专用配置组，之后只覆盖其内容；聊天/分支可能有各自的组副本。
- 勾选：普通随机模式使用当前选中的手动配置组；剧情增强模式优先使用当前有效场景组，否则使用平时配置组。自动生成的骰子显示在该组原有骰子之后，参与随机抽取。**不会新建配置组，也不会写入共享组库**。
- 自动骰子单独保存在当前聊天元数据中。每次更新或立即重新生成都**替换**此前的自动骰子列表，避免无限累积。原始手动骰子保持不变。改变当前选中组会移动附加区，无需再次请求模型。
- 追加部分支持临时编辑和暂停，下次自动生成会更新这部分。复制配置组或导出「当前配置」可将目前内容固化成独立配置；按组库单独导出只包含手动保存的原始配置。
- 切换聊天或聊天分支不复制实体配置组：各聊天保存自己的附加指令；原始共享配置组保持不变。
- 关闭自动生成仅停止调用，最后一次附加结果保留可用。取消勾选则恢复自动专用组模式；已保留的附加数据不会被静默删除，重新勾选后可继续使用。
- 已存在的自动专用组**不会自动删除**：它们可能包含用户手动修改过的内容，如不再需要，可自行从组库删除。

## 兼容与成本

原有设置、历史自动组、MVU、剧情增强条件及手动生成配置保持兼容。不额外请求 API，自动生成间隔、生成参数和失败回退逻辑保持不变。没有绑定可用剧情层时，追加模式在调用模型前报错，不创建任何组。

## 验证

新增覆盖追加模式周期更新、组库无增长、原始指令不被更改、聊天分支隔离、切换现有组、剧情层附加及无效绑定的自动化回归用例。CI 执行 `npm test` 和 Node 运行时代码语法检查。本次未运行真实模型端到端测试。
